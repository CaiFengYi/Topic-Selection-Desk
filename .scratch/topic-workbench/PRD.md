# 本地热点创作选题台首版规格

Status: ready-for-agent

日期：2026-10-27。

发布状态：已发布到本项目本地Markdown任务跟踪器。用户要求先建立前端原型、通过原型确认接口，再从前端进行测试；本规格已据此修订。ready-for-agent表示可以开始原型阶段，不表示原型已验收或接口契约已经冻结。

## Problem Statement

个人创作者希望从B站、抖音、微博的热点中发现创作机会：先理解事件语境、提取有出处且有辨识度的原词，再将其转成独立成立的短视频科普问题。标题或开场应让热点观众迅速产生联想，同时不借通用知识裁定具体争议、解释某次事故或替某方背书。

现有TrendRadar能够提供本地榜单和历史，终端验证已跑通Exa取材、DeepSeek提词与两种推荐方式，但使用仍依赖命令行和三个固定案例。用户无法在同一页面中选择任意热点、补充材料、修正词义、勾选关键词、换一批、编辑并选用草稿，也缺少完整的状态展示与恢复体验。

此前真实验证已经说明：请求成功、引用有效、内容可用和用户选用是不同层次。部分热点事实仍有缺口，一些候选需修改或知识核验。系统需要保留这些差异，材料过少时直接警告，不通过自动补查、重试或付费诊断消耗额外额度。

## Solution

提供仅在本机使用的选题台，将已确认流程落地为可保存、可恢复的交互：

榜单点选或手动添加热点 → 用户发起研究 → 展示研究卡、材料、来源分歧、取材警告和关键词 → 用户点击默认“直接推荐”或使用“我来挑关键词” → 生成最多三个选题草稿 → 编辑、换一批或选用多个草稿。

首版支持词义修正及人工补充材料，保持原词和引用可追溯。换一批只重新生成候选，保留已有研究和历史轮次。所有本地查看、修改、保存和选用操作均不触发收费调用；付费操作明确由用户动作触发，并继续受原累计预算及调用限制约束。

首版完成到选题草稿及选用状态，不启动知识核验工作流、脚本或视频生产。

开发顺序采用前端原型优先：先以模拟数据和接口响应建立可操作原型，验证已确认流程；再依据页面实际需要确认接口契约，接入本地服务，并从同一前端完成联调和验收。原型与模拟数据明确标注，不使用付费检索或模型调用来演示交互。

## User Stories

以下故事的使用者均为同一位个人创作者。

1. 作为个人创作者，我希望在一个页面查看B站、抖音、微博本地榜单，以便挑选值得投入的热点。
2. 作为个人创作者，我希望看到条目的平台、标题、排名、来源链接及采集时间，以便判断来源并回看原页面。
3. 作为个人创作者，我希望从榜单点选热点进入研究，以便省去复制命令和手动整理输入。
4. 作为个人创作者，我希望手动填写热点标题或描述，以便研究尚未被本地榜单收录的话题。
5. 作为个人创作者，我希望可选补充来源链接、地点、时间及关注点，以便缩小研究范围。
6. 作为个人创作者，我希望两种入口进入相同的研究和选题流程，以便保持一致的使用方式。
7. 作为个人创作者，我希望无本地榜单数据时得到明确提示，以便不把旧示例数据误当成当前热点。
8. 作为个人创作者，我希望刷新榜单只采集和保存数据，以便在人工选定热点前不发生整榜AI分析费用。
9. 作为个人创作者，我希望粘贴评论、字幕片段或梗的解释并注明来源，以便补充公开网页没有说明的语境。
10. 作为个人创作者，我希望人工补充材料被明确标注，以便知道哪些内容尚未回查原页面。
11. 作为个人创作者，我希望研究只在我主动发起后运行，以便控制注意力和API消耗。
12. 作为个人创作者，我希望看到研究正在执行的阶段，以便知道任务进度而不用反复点击。
13. 作为个人创作者，我希望无法定位具体事件时先选择候选或补充信息，以便避免不同事故或事件的材料混用。
14. 作为个人创作者，我希望同一事件中的车型、数字或说法差异被保留而不反复阻断，以便在分歧未解决时仍能理解语境。
15. 作为个人创作者，我希望每个来源保留标题、链接、可获得的发布时间、读取时间及实际文本，以便核查系统用了什么材料。
16. 作为个人创作者，我希望搜索结果、已读正文、重复内容和读取失败分别标注，以便判断取材情况。
17. 作为个人创作者，我希望同一声明的转载被识别为同一材料链，以便不把多家转载当成独立佐证。
18. 作为个人创作者，我希望研究卡注明哪些是来源一方说法及谁说的，以便不把厂商说明误读为调查结论。
19. 作为个人创作者，我希望事件时间、材料发布时间、读取时间及研究截止时间分开，以便不混淆不同时间含义。
20. 作为个人创作者，我希望未知时间或缺失信息如实标明，以便不被模型猜测误导。
21. 作为个人创作者，我希望材料过少时直接看到取材警告，以便知道当前研究可能受限。
22. 作为个人创作者，我希望警告说明已有的返回数量、读取结果及已知错误，以便看懂限制而不用承担检索调试。
23. 作为个人创作者，我希望材料异常不触发自动补查、重读、重试或付费诊断，以便避免进一步浪费费用。
24. 作为个人创作者，我希望系统保留已有材料及失败记录，以便失败后仍能查看本次取得的内容。
25. 作为个人创作者，我希望研究缺口清楚可见，以便不将尚未证实的热点说法作为创作结论。
26. 作为个人创作者，我希望提词只给出少量有价值的关键词，以便快速选择创作重点。
27. 作为个人创作者，我希望原词保留完整的物件、数字、百分数和单位，以便保留热点辨识度。
28. 作为个人创作者，我希望每个原词附带连续原文摘录和来源，以便逐字回查。
29. 作为个人创作者，我希望肯定、否定、争议及来源归属语境被保留，以便不将否认改写成已经发生。
30. 作为个人创作者，我希望绰号的事件含义与字面联想分开，以便既理解梗也能合理延伸知识。
31. 作为个人创作者，我希望AI延伸概念与材料原词分开，以便不把创意误当成材料内容。
32. 作为个人创作者，我希望修正AI对词义的解释，以便让推荐基于正确语境。
33. 作为个人创作者，我希望修正解释时保留原词、引用和原AI解释，以便更正理解而不改写来源。
34. 作为个人创作者，我希望词义修正被后续推荐采用，以便纠正内容真正影响创作结果。
35. 作为个人创作者，我希望提词完成后停止并等待我操作，以便先看研究卡再决定是否生成选题。
36. 作为个人创作者，我希望点击默认“直接推荐”后由AI选择合适关键词，以便快速获得创作方向。
37. 作为个人创作者，我希望勾选关键词后推荐只围绕本轮所选词，以便明确控制创作重点。
38. 作为个人创作者，我希望可添加人工补词并保留其未核实线索身份，以便表达创意而不伪造事件事实。
39. 作为个人创作者，我希望旧补词被保留但不绕过本轮选择自动加入人工推荐，以便历史线索不干扰当前意图。
40. 作为个人创作者，我希望多个所选词可以分别产生选题，以便不被强行拼成一个不自然的视频。
41. 作为个人创作者，我希望每轮最多得到三个不同候选，并允许少于三个或没有候选，以便避免为了数量凑题。
42. 作为个人创作者，我希望候选展示标题、开场、知识问题、所用词、关联理由、画面方向及待查证事项，以便判断是否值得继续。
43. 作为个人创作者，我希望标题或开场保留有依据的具体原物件和数字，以便观众迅速联想到热点。
44. 作为个人创作者，我希望知识问题脱离具体争议仍能独立成立，以便未了解热点的观众也能观看。
45. 作为个人创作者，我希望每题聚焦适合60至90秒表达的主问题，以便后续能制作短视频。
46. 作为个人创作者，我希望未经核实的实验数据、类比和结论被列为待查证事项，以便避免把模型草稿直接当成科普事实。
47. 作为个人创作者，我希望调整关键词或词义后继续复用既有研究，以便不重复支付检索费用。
48. 作为个人创作者，我希望主动点击“换一批”获得新候选，以便当前方向不合适时继续探索。
49. 作为个人创作者，我希望“换一批”明示会消耗模型额度且只重新推荐，以便清楚此次付费动作的范围。
50. 作为个人创作者，我希望新一批尽量避开已有角度，以便获得更多可比较的方向。
51. 作为个人创作者，我希望查看历史推荐轮次及其当时使用的关键词和解释，以便比较和追溯。
52. 作为个人创作者，我希望编辑候选标题和开场并保存，以便将可用方向打磨成符合账号表达的草稿。
53. 作为个人创作者，我希望同一热点同时选用多个候选，以便分别推进多个独立知识主题。
54. 作为个人创作者，我希望每个草稿分别保存选用、修改或放弃的状态和记录，以便管理后续工作。
55. 作为个人创作者，我希望后续生成不覆盖已选用或已修改的草稿，以便保护已有工作。
56. 作为个人创作者，我希望选用不自动启动知识核验、脚本或视频生成，以便保留逐步决策的控制权。
57. 作为个人创作者，我希望刷新、重新打开或查看同输入结果时复用已有记录，以便不重复产生费用。
58. 作为个人创作者，我希望重复点击执行按钮不会创建重复付费任务，以便避免操作导致额外消耗。
59. 作为个人创作者，我希望看到累计计账、失败预留与预算上限，以便控制本轮花费。
60. 作为个人创作者，我希望下一次请求可能超过预算时被拦截，以便累计费用受约束。
61. 作为个人创作者，我希望价格快照失效、账号不可用或服务限流时得到明确提示，以便知道为何未执行收费请求。
62. 作为个人创作者，我希望失败或中断请求的费用预留不被清零，以便预算不会因重启而失真。
63. 作为个人创作者，我希望查看调用用量、耗时及费用估算依据，以便区分应用估算和账户实际扣款。
64. 作为个人创作者，我希望页面查看、编辑、保存、词义修正和选用都只在本地完成，以便这些操作不消耗API额度。
65. 作为个人创作者，我希望研究或模型失败时保留结果并显示失败阶段，以便不丢失已有工作或误以为任务成功。
66. 作为个人创作者，我希望关闭后重启仍能读取材料、修正、轮次、草稿和选用状态，以便持续运营而不依赖当前终端会话。
67. 作为个人创作者，我希望密钥不进入页面、日志、报告或版本控制，以便凭据留在本机配置中。
68. 作为个人创作者，我希望任意新热点能进入流程，同时旧案例、原报告和终端入口保持可读可用，以便新增能力不破坏现有成果。
69. 作为个人创作者，我希望先操作前端原型再接入真实服务，以便尽早确认页面和交互符合实际创作习惯。
70. 作为个人创作者，我希望原型用明确标注的模拟数据展示正常、警告、澄清和失败情形，以便不消耗API额度也能检查流程。
71. 作为个人创作者，我希望依据原型确认页面动作、请求响应字段和状态之间的接口契约，以便前后端对接有明确依据。
72. 作为个人创作者，我希望接入真实接口后仍从前端执行主要测试和验收，以便确认实际使用路径可以完整运行。

## Implementation Decisions

### 已确认的业务行为

- 人工初筛前移。榜单点选和手动添加使用统一的热点输入；不对整榜先做收费提词或推荐。
- 事件定位与来源分歧分别处理。只有无法判断是哪件事时暂停提词；同一事件中的来源分歧保留出处后继续。
- 取材使用Exa正式API的公开搜索与正文能力，模型沿用现有DeepSeek配置。用户补充的评论、字幕和解释属于人工补充材料，不标记为系统已回查的原网页。
- 每个事件沿用至多两次搜索、每次至多五条结果、至多一个五页正文批次的首轮限制。材料过少后不追加补查、重读、重试或付费诊断。
- 取材警告、研究缺口、引用有效性和用户选用是不同维度。材料数量不代表热度、事实真伪或独立证据数量；也不因警告就宣称单份材料已通过研究验收。
- 原词和摘录必须能回查取得的文本，搜索摘要、不可读页面及模型记忆不能冒充已读原文。无可用文本时如实报告未完成，不编造背景、关键词或出处。
- 词义修正与原研究结果分开，后续推荐采用修正后的解释，仍可查看原AI解释与原文。用户修正不自动证实事件事实。
- 提词完成后停止。直接推荐由AI从研究关键词中选取方向；人工推荐仅围绕本轮所选词，人工补词单独标记来源与未核实性质。
- 每批最多三个候选，允许零候选并说明原因。每个候选包含标题、开场、知识问题、所用关键词、关联理由、画面方向与待查证事项。
- 创作优先保留原物件、数字及单位，以独立知识问题展开。不得用纸替代踏板作为主线、将1612N无故改成1000N，也不得将来源一方说法改写成调查结论。
- 候选避免具体事件裁定、事故还原、辩护、辟谣或行情报道。题目强辨识度与独立知识内容并存，具体科学结论留待后续核验。
- “换一批”新增推荐轮次，只调用模型生成新候选，复用既有材料、当前关键词和修正；历史轮次、人工修改与选用不被覆盖。
- 相同输入的查看或重放使用缓存；显式请求新一批不能用旧缓存冒充新结果。每次新生成仍受费用限制。
- 同一事件允许多个草稿分别选用。选用仅表达继续打磨的意向，不启动下一阶段制作。
- 先建立前端原型、确认接口，再接入本地服务。原型用于确认界面、交互及契约；测试以用户在前端完成操作的路径为主，保留必要的预算、缓存和失败处理专项验证。

### 实现安排

以下安排来自对现有代码及首版实施方案的整理，是本规格的实现建议；与用户确认的产品行为区分，不代表新增代码已经存在。

- 第一阶段建立可点击的前端原型，模拟榜单、研究卡、关键词、推荐轮次和草稿；提供事件待澄清、材料过少、零候选、执行失败等可观察状态。原型不调用Exa、DeepSeek，不修改正式资料或费用账本。
- 根据原型明确各页面动作需要的请求与响应字段、任务和结果身份、执行状态、警告、错误、缓存复用及防重复操作约定，并记录可对照的响应样例。接口先作为候选契约，完成原型与接口确认后再推进真实服务对接，不提前声称已经冻结。
- 原型和正式对接阶段复用一致的接口约定，模拟响应与真实响应具有相同的业务含义。原型只能证明交互表现；真实持久化、预算与服务行为需在对接后验证。
- 新增独立的本地选题台服务和轻量网页，沿用现有Python及锁定环境；建议使用已有Starlette和Uvicorn，不增加前端构建链。服务仅监听本机回环地址。
- 复用现有榜单与采集能力。榜单刷新提供仅采集和保存的路径，不调用原版整榜AI分析；原版入口保持兼容。
- 将固定案例配置与通用研究过程分离，使任意热点拥有独立身份。旧案例的特定身份和比较验证要求继续保留，不能套用为所有领域的充分性判定。
- 复用已有Exa与DeepSeek客户端能力、脱敏、原文引用检查、缓存、预算预留和原子保存，不复制整套客户端或另建费用系统。
- 沿用既有SQLite读取榜单；研究、材料、人工补充、词义修正、选词、推荐轮次及草稿沿用JSON持久化，首版不引入另一套数据库。
- 材料记录保留来源身份、标题、链接、可取得的发布时间、读取时间、文本、读取状态与错误。人工补充材料另保留提交内容及用户提供的来源说明；未知信息留空或明确标注。
- 研究卡关联热点身份、材料、背景说法、关键词、证据链分组和缺口。关键词关联原词、意义、原文摘录、来源及语境；修正单独保存。
- 推荐轮次记录当时的推荐方式、关键词与解释快照、研究关联及候选集合。草稿以独立身份保存编辑和选用状态，避免不同轮次的同名编号互相覆盖。
- 现有历史补词会自动进入推荐的行为需要修正。人工推荐以本轮显式选择为准，持久保存历史词不等于本轮选中。
- 对外接口覆盖榜单读取及刷新、热点创建及读取、人工补充材料、事件澄清、研究发起、词义修正、当前选词、推荐发起、新一批、轮次与草稿读写、选用和任务状态。具体路由命名不构成规格约束。
- 发起操作返回任务身份，读取状态和结果不重新发起付费操作。重复提交同一次操作不能产生第二次收费请求；明确点击换一批则形成新操作。
- 研究和推荐在后台执行，首版串行处理付费任务。任务区分等待、执行、待事件澄清、完成、失败或中断；取材警告及研究缺口独立记录，不伪装为已证实状态。
- 共享现有累计5元账本，不重置历史计账与失败预留，不因新增入口或数据目录创建空账本。请求前预留费用，下一次可能超预算时不发起请求。
- SDK与客户端不隐式重试。中断后不自动恢复付费请求；已有结果和预留仍可读取。鉴权、余额、限流及价格快照问题按实际状态呈现。
- 记录模型实际返回名、token用量、耗时及费用估算依据，不将别名承诺为固定权重，不将预留或估算说成实际账单。

## Testing Decisions

### 已按用户要求调整的阶段与主测试入口

1. 前端原型阶段：使用模拟数据及接口响应，从页面操作检查两种热点入口、事件澄清、研究展示、关键词与词义修改、两种推荐、换一批、编辑及多选。模拟的执行、警告和失败状态必须可观察，不调用付费服务。
2. 接口确认阶段：结合原型逐项对照页面动作、请求响应字段、状态、警告、错误与防重复语义，形成可执行的前后端对接契约。由用户通过原型确认交互与接口后进入真实服务对接；不重新访谈已确认需求。
3. 前端联调阶段：页面连接真实本地选题台服务及隔离的临时存储，仅在Exa、DeepSeek外部请求边界提供可控响应。通过页面操作、重启后数据及实际请求计数验证完整流程。
4. 真实服务验收阶段：从同一前端触发预算内的真实取材与推荐，单独记录结果与限制，不把模拟交互通过称为真实服务验收通过。

主验收入口为浏览器中的完整创作流程，不依赖内部函数名、文件排列或组件结构。前端验收覆盖页面与对接行为，不能单独证明预算持久化、并发锁或客户端无隐式重试；这些必要检查继续复用已有边界测试，原29项终端离线回归保留，避免镜像测试实现细节。

### 行为验收

- 原型先可操作，正常、澄清、警告与失败状态可以通过前端演示；所有模拟数据和结果明确标注，真实API请求数及正式账本变更数均为零。
- 原型中每个业务动作都有对应的候选接口约定及响应样例；接口确认记录区分已确认契约与尚未对接部分，模拟与真实模式不混淆。
- 两种热点入口均能完成研究、等待用户点击、两种推荐、编辑及多选，并在重启后恢复。
- 使用未预置标题的材料夹具证明通用流程不依赖三个固定案例；另验证旧案例与终端兼容，不用通用夹具冒充真实新热点实测。
- 无法定位事件时显示候选或补充入口并停在提词前；同一事件的来源分歧仍可显示研究结果和归属。
- 原词、数字、单位、否定及说话者有明确输入与输出断言；伪造来源或不匹配摘录不能通过引用校验。
- 人工材料保留原始提交文本及来源身份，不能显示为已回查网页；同一声明的转载不变成多份独立事实佐证。
- 模拟只有一份可读正文、多页读取失败、结果重复及没有可引用文本，观察对应警告或未完成结果；断言没有追加搜索、正文读取、模型诊断或自动重试。
- 提词完成后的模型推荐请求数为零，直到用户点击推荐；词义修改、草稿编辑、选用、刷新及查看历史不增加付费请求数。
- 修正后的词义进入下一次推荐，原词及引用保持；旧轮次仍保留当时的解释，不被后来的修正改写。
- 人工模式只传本轮选词，保存过但未选中的人工补词不得混入；多个词不必都塞进同一候选。
- 每批最多三个候选；零候选有可见理由。候选可追溯到所用词，包含明确问题、关联理由、画面方向与待核验事项。
- 明确换一批使模型请求数恰好增加一次、检索和正文请求数不增加，生成新轮次；重复点击和刷新不重复扣费，预算不足时请求数不增加。
- 从多个轮次选用同一热点下的多个草稿，编辑其中一个后换一批、切页及重启，原选择和修改仍保留。
- 覆盖无效凭据、余额不足、限流、超时、服务错误和无效模型输出；既有结果仍可读，不隐式重试，费用预留不因失败或重启清零。
- 覆盖预算即将耗尽、价格快照过期和并发重复操作，证明新付费请求在边界前被拦截，不在测试中消耗真实额度。
- 检查浏览器响应、日志、报告和持久化结果，不包含测试凭据或真实密钥。
- 榜单读取和刷新不触发整榜模型分析；无当天数据时不把历史示例当成新采集。

### 既有先例与真实验收

- 已有29项终端离线测试覆盖预算持久化、预留、锁、引用、否定语境、人工选词、缓存、失败保留与SDK无隐式重试。这些测试是回归基础，不代表页面或新增功能已通过。
- 已保存三例真实取材和推荐证据，两种推荐方式均已有真实调用记录；内存倒挂研究仍不足，部分标题仍需编辑，科学结论和用户审核不能据结构校验自动通过。
- 真实端到端验收单独记录，在核价有效、账号可用且原累计预算充足时验证一个未预置热点。记录来源可读性、用量、耗时、估算及失败项，不为取材过少追加请求；无法完成则如实报告，不宣称通过。
- 创作质量使用人工复核：原物件和数字是否保留，知识问题是否独立，是否仍暗示事件结论，是否出现无条件的比较或未经核验的类比。不用关键词字符串命中代替内容质量判断。
